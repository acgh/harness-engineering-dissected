1of 9The one idea

An agent is a model plus a harness

Agent=Model+Harness

The model supplies the intelligence. The harness is everything else: the runtime that couples the model to the world through a loop, tools, context management, safety controls, orchestration and extension points. Harness engineering is the craft of designing and evolving that runtime. It got its name in February 2026.

The paper is the first source-level reference for that craft. The authors read the code of eleven production coding harnesses (Claude Code, Codex CLI, Gemini CLI, Mistral Vibe, OpenHands, Aider, Mini-SWE-Agent, Hermes, Pi, OpenCode, OpenClaw) plus one "meta-harness" that orchestrates the others (Databricks' Omnigent). They do not benchmark or rank anything. They describe how the systems are built and compare them.

Four things a harness is not

Not quite a scaffold

Near-synonyms. "Scaffold" is the structural code (loop, registries); "harness" is the shipped runtime around it.

Not a framework

You import LangChain or AutoGen to build an agent. You work inside a harness. In 2026 this line is dissolving from both sides.

Not an eval harness

The SWE-bench "harness" wraps an agent to test it. An agent harness wraps a model to make it act. Opposite directions.

Not an orchestrator

A meta-harness coordinates harnesses from above and has no editing loop of its own.

3of 9The surprising floor

A 100-line harness reaches the frontier range. The other 99.99% is for something else.

Mini-SWE-Agent implements all seven subsystems in about 100 lines of Python: a while loop, one prompt template, one bash tool, a growing message list, a step and cost limit, no sub-agents. Its self-reported SWE-bench Verified score (74%+) sits in the same range as systems three orders of magnitude larger.

messages = [system_prompt, task]
while True:
    check_limits()                        # step count, cost, wall clock
    reply = model(messages)               # one inference
    messages.append(reply)
    if reply.is_exit: return reply
    for action in reply.actions:          # usually one bash command
        obs = subprocess.run(action)      # fresh subshell each time
        messages.append(obs)              # history grows without bound

So where does a million lines of Codex go? Not into completing tasks. The paper's first observation: loop sophistication does not predict benchmark performance. Production mass buys safety, user experience, extensibility, robustness and cost control, and increasingly clients and transport. About three-fifths of OpenCode's non-test source is its TUI, web, desktop and SDK clients; Codex spends six-figure line counts on app-server transports, plugins and a realtime voice layer.

What this means for youStart tiny. A working loop is an afternoon of work. Everything you add after that should answer a failure you observed or a production need (safety, cost, UX), not a feeling that "real agents are complicated".
4of 9The playbook

Ten decisions for your first harness

Distilled from the paper's 18 recommendations, in the order you will meet them. Each one names its evidence and the moment to upgrade. The deep track has all 18 with full evidence.

Write a plain while loop

Prompt, call the model, run the tools, append results, repeat until the model stops calling tools. Don't import a framework for this.

Upgrade when you have three or more independent turn policies (turn cap, cost cap, auto-compaction, context warnings, read-only mode): make each a middleware, as Mistral Vibe does, instead of branches in the loop.

Since thenIndependent rebuilds keep landing on the same small loop (Ark’s is 18 lines), and on one model Claude Code and the 100-line mini-SWE-agent scored within 5 points of each other. What does a harness buy?

Start with one bash tool

Add tools only in response to failures you saw. A common order: read/write file once bash output truncates badly, grep/glob once find feels clumsy, a search-and-replace tool once full-file rewrites waste tokens.

Upgrade when you pass about 15 tools: hide most of them and let the model search for them (deferred loading, see the deep track).

Since thenRight for frontier models: the strongest model tested scored higher bash-only and cost 30–53% less. A 30B open model gained 15 points from typed read/search/edit tools. Choose by model tier. Harness design study

Edit by exact, unique match

The edit tool takes an old string that must occur exactly once and a new string. Reject ambiguity with a clear error. Never edit by line number: models drift on line numbers more than on context.

Upgrade when you target open or weaker models: add a fuzzy matching cascade (OpenCode, Hermes) or an LLM "edit fixer" subcall (Gemini CLI).

Auto-load AGENTS.md files

Walk from the repo root to the working directory and inject every context file you find. Read your neighbours' filenames too (CLAUDE.md, .cursorrules): the newest harnesses all do.

Upgrade when repos get deep: load nested files just-in-time, when a tool first touches their subtree.

Since thenKeep the loader; keep the file short, human-written and current. Auto-generated files didn’t change success and cost 20–23% more; agents obey a stale convention file even against working code. Evaluating AGENTS.md Coherence debt

Compact at a threshold

When the conversation nears the context window, summarize the old part with the model and keep a recent tail verbatim. Seven of the eleven systems converged on this. Wire the same routine to fire when a call overflows.

Upgrade when sessions get long: pass the previous summary back in and merge it, rather than re-summarizing from scratch, so early decisions survive.

Since thenIt pays mostly when the window is tight. Drop old tool outputs before summarizing, and re-inject your rules afterwards: summaries lose “how to work” and “don’t touch” instructions about 6× more often than the spec. Whether to merge summaries or never summarize a summary is still contested. Compaction-friendly benchmarks CliffCompaction

Use grep, not embeddings

Retrieve code with ripgrep, glob, tree-sitter and the file system. None of the eleven systems uses vector search over code: code has deterministic structure, and an index goes stale as soon as the agent edits a file.

Upgrade when you can prove, on held-out tasks, that semantic retrieval beats ripgrep + tree-sitter. Nobody in the corpus has.

Since thenNo later study showed embeddings beating grep for a coding agent. What decides outcomes is whether the facts an edit depends on are in context when it’s written. Coherence debt

Pick safety by deployment context

For a developer tool: approval modes (plan / default / auto-approve) plus pattern rules over commands and paths. For enterprise, shared or automated runs: an OS-level sandbox plus policy-as-code and audit trails.

Always write the rules as data, not imperative code, and keep a hard floor (rm -rf /, mkfs, fork bombs) that even "YOLO" mode cannot bypass.

Since thenAuto-approve without a floor took attack success from 29% to 96%. Model-based auto-reviewers were fooled when the harness relabeled tool output as a user request. Also protect the agent’s own config, memory and skill files. HarnessSecurity-Bench Instruction privilege escalation

Ship the cheap caps

Max turns, max cost, wall-clock limit, a cap on consecutive malformed replies, and a counter for repeated identical tool calls. Each costs a dozen lines.

Skip elaborate stuck detectors until you've seen your agent loop in ways the caps miss.

Since thenThe cheap recovery that matters most: re-prompt after an output-length stop. On the same model one harness lost 33 runs to it, another lost 1. What does a harness buy?

Stay single-agent

Multi-agent setups use roughly 15× the tokens of a plain chat (Anthropic's figure), and most coding work is less parallel than it looks.

Upgrade when you can point to a breadth-first exploration phase (parallel codebase research) where isolated contexts clearly beat serial search. Keep those sub-agents in-process.

Since thenSplitting tightly coupled changes across sub-agents hurt, and a “coordinator” named only in a prompt changed nothing. The exception: multi-day work shaped like a dependency graph, where worker fan-out did best. Measuring coordination LoopsBench

Extend with skills first, MCP second

Skills (a folder with a SKILL.md) package know-how and workflows; MCP connects external systems. Load skill metadata up front and the body only when needed.

Treat third-party skills as packages: trust tiers, scanning and quarantine are the emerging baseline.

Since thenScans flagged vulnerabilities in about a quarter of community skills, and payloads hidden in a skill’s code examples got past defenses 12–34% of the time. Pin skills, scan their examples, enforce declared tool scopes. Skills in the wild PoisonedSkills

5of 9What nobody uses

Two technologies you probably expected, absent from all eleven

No agentic framework

Across ~4M lines, no agent runtime imports LangChain, LangGraph, LlamaIndex, AutoGen, CrewAI, Pydantic AI, Genkit, Semantic Kernel, Google's ADK or a dozen smaller libraries. Gemini CLI uses neither of Google's own. Every loop is hand-rolled on asyncio, Promises or Tokio.

No vector RAG over code

Zero systems retrieve code with embeddings. They use ripgrep, glob, tree-sitter and auto-discovered Markdown context files. The one default use of embeddings (OpenClaw) is for chat memory, never for the source tree.

Why? When the agent mutates real code, debuggability wins: frameworks hide the exact prompt and response, and their failure modes (silent prompt corruption, opaque caching, schema drift) get expensive. For retrieval, code already carries paths, types and parse trees, changes minute to minute, and every machine ships a near-perfect search tool. The 2026 twist: the harnesses did not adopt frameworks, they became them (Quick 9).

6of 9Standards to plug into

What the field converged on

If you support these, your harness works with the ecosystem other harnesses already use.

  • Context files: AGENTS.md (and vendor variants CLAUDE.md, GEMINI.md), discovered hierarchically.
  • Skills: a directory with SKILL.md plus YAML frontmatter (name, description), per the agentskills.io spec. The shared path is .agents/skills/.
  • Lifecycle hooks: events like PreToolUse, PostToolUse, Stop that can block or rewrite. Codex copied Claude Code's event names verbatim.
  • MCP for external tool processes (Slack, databases, internal APIs).
  • ACP (Agent Client Protocol): serve it and editors, host harnesses and meta-orchestrators can all drive your agent.

A minimum viable harness to copy

The paper closes with a ~90-line scaffold that implements ten of its eighteen recommendations. Below is a condensed rewrite of the same design; R1…R18 marks point to the recommendation each part follows. Bring your own Model adapter.

"""Minimum viable coding harness: a sketch in the spirit of the paper's section 16.10.
Copy it, run it on a real repo, then add only what your observed failures demand."""
import json, pathlib, subprocess
from dataclasses import dataclass, field
from typing import Protocol

class Model(Protocol):                          # R2: you own the provider seam
    def complete(self, messages: list[dict], tools: list[dict]) -> dict: ...

# ---- tools: bash first, then three file tools (R3) ------------------------
def clip(s: str, n: int = 25_000) -> str:       # never flood the context window
    return s if len(s) <= n else s[:n] + "\n...[truncated]"

def bash(cmd: str) -> str:
    """Run a shell command in the repository."""
    r = subprocess.run(cmd, shell=True, capture_output=True, text=True, timeout=120)
    return clip(f"exit={r.returncode}\n{r.stdout}\n{r.stderr}")

def read_file(path: str, offset: int = 0, limit: int = 2000) -> str:
    """Read a file, with line numbers."""
    lines = pathlib.Path(path).read_text().splitlines()[offset:offset + limit]
    return clip("\n".join(f"{offset + i + 1:5}  {l}" for i, l in enumerate(lines)))

def write_file(path: str, content: str) -> str:
    """Create or overwrite a whole file."""
    pathlib.Path(path).write_text(content)
    return f"wrote {len(content)} chars"

def replace(path: str, old: str, new: str) -> str:      # R5: exact, unique match
    """Replace one exact snippet that occurs exactly once."""
    p = pathlib.Path(path); text = p.read_text(); n = text.count(old)
    if n != 1:
        return f"ERROR: snippet found {n} times; it must be unique"
    p.write_text(text.replace(old, new, 1))
    return "OK"

TOOLS = {f.__name__: f for f in (bash, read_file, write_file, replace)}

# ---- hierarchical context files, root to leaf (R6) ------------------------
def project_context(cwd: pathlib.Path = pathlib.Path.cwd()) -> str:
    files = [d / "AGENTS.md" for d in reversed([cwd, *cwd.parents])]
    return "\n".join(f"<context path='{p}'>\n{p.read_text()}\n</context>"
                     for p in files if p.exists())

# ---- the loop; policies stay small, separate checks (R1, R7, R18) ---------
@dataclass
class Harness:
    model: Model
    max_turns: int = 50                          # cheap caps: a dozen lines
    max_cost: float = 5.0
    compact_at: int = 120_000                    # tokens; a buffer below the window
    messages: list = field(default_factory=list)
    turns: int = 0
    cost: float = 0.0

    def tokens(self) -> int:                     # crude chars/4 estimate
        return sum(len(json.dumps(m)) for m in self.messages) // 4

    def compact(self) -> None:
        if self.tokens() < self.compact_at:
            return
        # keep the recent 30% verbatim (real harnesses cut at turn boundaries)
        tail = self.messages[-max(4, len(self.messages) * 3 // 10):]
        s = self.model.complete(self.messages + [{"role": "user", "content":
              "Summarize: goal, decisions taken, open issues, files touched."}], tools=[])
        self.messages = [self.messages[0],
                         {"role": "user", "content": "Summary so far:\n" + s["content"]}] + tail

    def run(self, task: str) -> str:
        self.messages = [
            {"role": "system", "content": "You are a coding agent.\n\n" + project_context()},
            {"role": "user", "content": task},
        ]
        schemas = [{"name": n, "description": f.__doc__} for n, f in TOOLS.items()]
        while True:
            if self.turns >= self.max_turns or self.cost >= self.max_cost:
                return "stopped: budget reached"
            self.compact()
            resp = self.model.complete(self.messages, tools=schemas)
            self.turns += 1
            self.cost += resp.get("cost", 0.0)
            self.messages.append(resp)
            if not resp.get("tool_calls"):      # no tool call: the model is done
                return resp.get("content", "")
            for call in resp["tool_calls"]:     # serial on purpose; parallelize reads later
                try:
                    out = TOOLS[call["name"]](**call["args"])
                except Exception as e:          # errors go back to the model as text
                    out = f"ERROR {type(e).__name__}: {e}"
                self.messages.append({"role": "tool", "tool_call_id": call["id"],
                                      "content": clip(str(out))})

Deliberately left out, because the corpus diverges on them: a sandbox (depends on deployment), multi-agent (defer it), MCP and skills (extensions, not core). The paper's conjecture: on a frontier model, a scaffold like this would match Mini-SWE-Agent's numbers, and going beyond them is mostly a model question.

PaperMinimal floors reach frontier-range scores.

NowConfirmed and sharpened: with the model fixed, harness swaps move pass rate a few points but cost 3–40×. The per-call preamble (system prompt plus tool schemas) times step count sets the bill.

Pick tools by model tier

PaperStart with bash; add tools on observed failures.

NowFrontier models do better bash-only, and cheaper. Weaker open models need typed read, search and edit tools: two thirds of one 30B model’s bash-only Terminal-Bench runs died calling tools that didn’t exist.

Compaction: elide, then summarise

PaperSummarise at a threshold; keep a verbatim tail.

NowWorth it mainly when the window binds. Tool calls and results made up 84% of the context in one measurement, so cutting old tool output does most of the work; summaries drop process rules, so re-inject them after each compaction.

Context files: short and specific

PaperAuto-discover AGENTS.md everywhere.

NowKeep the loader, change the content. Generated files add cost, not success; directory overviews don’t help; a two-line note about one real failure removed it in 5 of 5 later sessions.

Your own files are attack surface

PaperApproval modes, sandbox, rules as data, a YOLO floor.

NowAll still right. Add: write-protect the agent’s config, memory and skill folders, and keep track of where content came from when you rebuild context for sub-agents, goals or scheduled runs.

PaperTreat third-party skills as packages.

NowOne scan flagged about a quarter of community skills as vulnerable (a repository-aware recheck puts the truly suspicious share near 0.5%), and abandoned repos behind skill indexes can be hijacked. Pin by content, scan bundled scripts and examples.

PaperStay single-agent until parallel search clearly pays.

NowHolds for coupled edits. Naming a coordinator in a prompt changed nothing; multi-day dependency-graph work is where worker fan-out did best (still only 25% of tasks solved).

9of 9Where it's heading

The harness became a platform in the first half of 2026

  • Harnesses became libraries: the Claude Agent SDK, openai-codex, and the OpenHands SDK let you import the whole harness.
  • Framework vendors shipped harnesses: LangChain's Deep Agents, Pydantic AI Harness, Strands harness-sdk. All landed on the same shape: loop, tools, skills, sub-agents, hooks, MCP, sessions.
  • Platform economics arrived: plugin and skill marketplaces with trust tiers, importers for rivals' session files (Codex reads Claude Code's), enterprise device-management config layers.
  • A layer appeared above: Omnigent drives 23 harness adapters behind one API, with a shared policy plane and sandbox.
  • Imitation replaced coincidence: in one quarter, distinctive features spread to other systems within weeks.

The competitive unit of the field is no longer the agent loop; it is the ecosystem surface around it.

The study at a glance

§1, §4, §5, §15.6

A descriptive, source-level anatomy of eleven production coding harnesses along seven dimensions, with a one-quarter longitudinal diff. No benchmarks, no rankings.

Updated November 2026Each subsystem section now ends with What other research measured: findings from 49 papers by other groups that benchmarked, attacked or optimised these designs. The verdict on every recommendation is in What was measured; all papers are in the explorer.

Corpus. Four provider-native flagships (Claude Code, Codex CLI, Gemini CLI, Mistral Vibe) and seven open-source systems chosen to span the field: OpenHands (event-sourced SDK), Aider (13 edit formats), Mini-SWE-Agent (the 100-line floor), Hermes (fastest-growing, self-improving skills), Pi (minimal-core countertrend), OpenCode (most-starred dedicated coding agent, client/server), and OpenClaw (a multi-channel assistant gateway, kept as a non-coding contrast point). Omnigent, a meta-harness, is a second contrast point and is not scored on the seven dimensions. Three languages, three orders of magnitude in size.

Method. Each system is read along D1 loop, D2 LLM integration and model–agent co-design, D3 tools and actions, D4 memory and context, D5 safety and permissions, D6 multi-agent orchestration, D7 extensibility. Eight systems were already audited in April 2026; their snapshots were kept and diffed against July, giving a controlled longitudinal sample. Dependency manifests and imports were swept twice, three months apart, across all twelve trees.

Two kinds of claim. A lesson the authors drew from their own revision: inventory claims (tool counts, feature cells, version pins) decay in weeks, while structural claims (loop taxonomy, subsystem anatomy, the absences) have proven durable. Three April observations had to be substantively revised (2, 6 and 11 below are flagged).

Caveats to carry: Claude Code is analysed from a publicly circulated March 2026 source snapshot, not the shipping binary (2.1.206). Benchmark figures are self-reported on different models and dates. Where counts are sensitive to OpenClaw, read "10 coding harnesses" figures for strictly-coding claims. Code sizes are order-of-magnitude only.

Definition & genealogy

§2.1–2.2, §3

The harness is everything except the model. The term is five months old in this paper's frame, and it already has practitioner guides, formal definitions and automated-evolution research.

The paper adopts Macedo's definitional core (the layer that wraps a language model and turns it into an agent able to act on a repository) and extends it with the seven-subsystem decomposition grounded in source. A footnote enjoys the irony: the term was named inside LangChain, whose libraries appear in none of the runtimes studied. LangChain's answer was not lobbying but shipping its own harness, Deep Agents, which independently converged on the same conventions (SKILL.md skills with progressive disclosure, AGENTS.md memory, sub-agents, a todo tool).

D1

The agent loop

§6, Table 5

Everyone runs ReAct. What differs is concurrency, state, stuck handling and, more and more, what happens at the exit: guards that veto a premature "done".

MinimalMini-SWE-Agent: a linear while over one bash tool.
MaximalOpenHands: an event-sourced conversation over a persistent event log, executing parallel action batches.

Inner loop vs outer loop

"Loop engineering" entered circulation in June 2026: Steinberger's dictum to stop prompting agents and instead design loops that prompt them, and Osmani's anatomy of triggers, topology, verifiers and stop rules. The paper treats it as complementary: harness engineering builds the inner action–observation cycle; loop engineering composes it from outside into self-sustaining outer loops. The seam is already in the code as the outer verification loop pattern: OpenHands' /goal endpoint runs an LLM judge after each run and either re-prompts or stops; Hermes' verify-on-stop guard vetoes the inner loop's own exit.

How each system builds it

event-sourced
OpenHands

LocalConversation drives Agent.step(); every event is appended to a persistent EventLog (one file per event, flock locking, secret redaction). The LLM sees a cached projection of the active branch of a conversation tree with a movable head, so replay and fork are first-class. One LLM call per step, all tool calls run as a batch, optionally parallel through a ParallelToolExecutor with a concurrency limit (default 1) and resource locks keyed on declared resources (files, terminal, browser): only same-resource calls serialize. The StuckDetector's five scenarios survived the rewrite, now configurable and on by default.

streaming + safety batches
Claude Code

SSE streaming with fine-grained block events. Tool calls are partitioned in a single-pass reduce by isConcurrencySafe, which defaults to false: read-only tools (grep, glob, read) opt in and batch together, writes (edit, bash) run alone; up to 10 concurrent via a semaphore. No automated stuck detection. Stops on end_turn.

Tokio state machine
Codex

An async Rust state machine: a Session consumes streamed ResponseItems (SSE or WebSocket) and runs tool calls through FuturesOrdered in a dedicated ToolCallRuntime, ordered but parallel. A per-tool supports_parallel flag (default false) gates an execution lock. No stuck detection.

async generator + scheduler
Gemini CLI

Yields typed stream events to the UI; a state-machine Scheduler walks each call through Validating → Executing → Completed/Errored. Hybrid loop detection: SHA-256 hashing aborts on 5 identical tool calls or 10 identical content chunks; after 30 turns an LLM self-check runs at an adaptive interval. 100-turn session ceiling, 11 lifecycle hook events. Since v0.45, file mutators are forced sequential, and uniquely the model gets a wait_for_previous boolean on every tool schema to serialize calls itself.

middleware pipeline
Mistral Vibe

Each iteration first walks a stack of six middlewares (turn limit, price limit, token limit, auto-compact, context warning, read-only gate), then runs tools concurrently as asyncio tasks. Swapping the middleware composition yields six agent profiles (default, plan, accept-edits, auto-approve, explore, lean) from one loop. Plan mode is structural: a plan file is the only writable target and exit_plan_mode emits a review event.

linear while
Mini-SWE-Agent

No state machine, no events, no concurrency; the message list grows unbounded. The design isolates model capability from scaffold complexity. Even the floor drifts up: v2.4 added a wall-clock limit and a cap on consecutive malformed actions, a minimal stuck detector.

budget + stop-guards
Hermes

A thread-safe IterationBudget (default 90, code-execution iterations refunded, a final grace call to summarize). Eleven enumerated exit reasons. The verify-on-stop guard turns a text-only reply into a continuation if the turn edited code without fresh verification evidence. Stuck hashing warns after 2 identical failures, halts after 8, but the hard stop ships disabled. Parallel on 8 workers only for read-only or non-overlapping paths; mid-turn user steering is spliced behind an anti-injection marker.

functional core
Pi

~790 lines; no planner, reflection, turn cap, stuck detection or cost kill-switch, all documented refusals. steer() injects input after the current tool calls; followUp() drains only when the agent would stop. Parallel by default with a per-file mutation queue. Truncation-poisoning guard: if the reply hit the length limit, all its tool calls fail unexecuted, because salvaged streaming arguments can validate while silently incomplete. ~40-pattern transient retry list; one-shot compact-and-retry on overflow.

log-as-queue
OpenCode

A literal while(true) where the message log is the work queue: pending sub-agent spawns and compactions are persisted message parts dequeued one per iteration, so the loop resumes across restarts for free. No default step cap; a configured cap appends a message saying tools are disabled. Three byte-identical calls raise a doom_loop permission ask, letting the user decide. Overflow is never retried; it flips to compaction.

reflection
Aider

run_one() applies edits, then lints (syntax → compile → flake8, with tree-sitter context around error lines), runs tests and checks unresolved file mentions; issues trigger a reflected message, up to 3 times. No tool-call loop: a turn ends when the stream ends. Cousins: Gemini CLI's edit fixer, OpenCode's LSP diagnostics on every edit, Hermes' verify-on-stop.

event-driven
OpenClaw

An ACP-driven event loop with RPC isolation; sessions end the loop; rate limiting instead of stuck detection.

Claude Code: recursive composition

Three levels: ad-hoc sub-agents, typed agent definitions, and coordinator mode. Definitions (JSON/Zod) carry description, prompt, tool allow/deny lists, model, turn limits, permission mode, MCP bindings, isolation, background flag and skills, and load in priority order built-in → plugin → user → project → flag → policy-managed (later wins). Built-ins: Explore, Plan, VerificationAgent.

Spawning through AgentTool forks the parent's context along six dimensions: a linked AbortController (parent abort kills the child, not the reverse); a cloned LRU file-state cache; suppressed permission prompts for async agents; no-op app state for async agents; fresh denial tracking; a fresh tool-decision map. The parent's rendered system prompt is frozen at fork time and passed verbatim, so cache hits survive fork and resume and feature-gate drift cannot invalidate them.

Coordinator mode (env var or feature gate): a lead agent with AgentTool and SendMessageTool runs Research → Synthesis → Implementation → Verification; workers report via <task-notification> XML and are limited to a 16-tool whitelist: FileRead, WebSearch, TodoWrite, Grep, WebFetch, Glob, Bash, PowerShell, FileEdit, FileWrite, NotebookEdit, Skill, SyntheticOutput, ToolSearch, EnterWorktree, ExitWorktree.

Codex: a thread tree

AgentControl is the control plane, AgentRegistry tracks live agents. Why frameworks lose here. Anthropic's Building Effective Agents warned that frameworks add abstraction layers that obscure prompts and responses and make debugging harder; every commercial provider followed that advice. When the agent mutates real code, silent prompt corruption, opaque caching and version-incompatible tool schemas are too expensive to shrug off.

Why RAG loses here. Code carries dense deterministic structure (paths, language servers, parse trees, types); it changes minute to minute, so indexes go stale by construction; ripgrep, find and glob are already near-optimal. CodeRAG-Bench found retrieval gains highly variable: large for documentation and library lookup, marginal where the model already knows enough.

Five trade-off axes

§13.4

Every harness is a position on five axes. The fifth, scaffold complexity versus model capability, is the one that matters most philosophically.

axis 1
Simplicity ↔ capability

Mini-SWE-Agent reports 74%+, Codex 69.1% on SWE-bench Verified, on different models, runs and configurations (unsandboxed vs sandboxed). No head-to-head conclusion; the point is that Codex's extra code is not task-completion logic.

axis 2
Safety ↔ autonomy

More safety infrastructure (Codex, Claude Code) means more friction per action; less (Mini-SWE-Agent, Aider) means speed but no enterprise fitness without added safeguards.

axis 3
Coupling ↔ agnosticism

Provider features vs lock-in. Revised by Observation 2: multi-provider systems can reach the features at a maintenance cost; only the update loop stays proprietary.

axis 4
Monolithic ↔ modular

Codex's 126-crate Rust workspace optimizes type safety and performance; Mini-SWE-Agent's single file, comprehension; Pi moves the axis to runtime composition; OpenClaw's SDK and OpenCode's client/server split buy extensibility and embeddability.

axis 5
Scaffold ↔ model capability

Current models succeed with minimal scaffolding. Production systems build scaffolding because users need it for safety, reliability and workflow integration, not because models need it to finish tasks.

The platform turn: from tool to platform

§14.1–14.3, Table 15

The April edition's cautious "CLI-as-framework" hypothesis is now a thesis: the harness is the framework. Developers don't import it; they work inside it, and their "program" is a task plus a tree of Markdown files.

A framework traditionally provides a loop, a tool registry, a memory layer, a configuration surface and an extension mechanism. Every production harness ships all five (Pi matches all but MCP). The "API" is the filesystem, the terminal and git; the configuration language is CLAUDE.md, AGENTS.md, GEMINI.md and SKILL.md.

signal 1
Skills as declarative programs

A skill declares what to do (the body), when to activate (paths, PathTrigger, requires) and what tools it may use: a plugin whose language is English plus YAML, now with registries and agent authors.

signal 2
Hooks as the extension substrate

A Claude Code distinctive in April; in nine of eleven systems by July (all but Aider and Mini-SWE-Agent). Codex uses Claude Code's event names; OpenHands allows an agent as a hook handler; Pi is an event bus. Developers write inside the agent.

signal 3
The loop is the workflow engine

Coordinator phases, Codex's update_plan and /goal, OpenHands' judge-audited goal loop: the CLI subsumes the build system, task runner and IDE.

signal 4
The harness as a service

OpenCode embeds an HTTP server with an OpenAPI spec and generated SDK; every UI is a client. OpenHands exposes conversations behind an OpenAI-compatible gateway: the agent as a model. Mistral Vibe teleports sessions to a hosted runtime; Claude Code pairs its SDK with a hosted Managed Agents API.

The meta-harness layer: Omnigent

§14.4

A bet that the harness is becoming a commodity component and that durable value sits one layer up: compose, police, sandbox and share sessions across eleven vendor harnesses, re-implementing the expensive parts and arbitraging the proprietary ones.

Apache 2.0, ~1M lines total, ~312K production Python. Declared capabilities are reconciled against a conformance bench (basic turns, tool calling, streaming, interrupts, model override, policy denial), with live verification for the four flagship SDK adapters and best-effort declarations for the rest: harnesses tested like hardware. The egress proxy runs its own CA with per-host default-deny rules and hosts a secretless credential proxy, swapping synthetic placeholders for real tokens in flight (Codex ships the same idea in its network-proxy crate).

It does not pretend harnesses are equivalent: per-harness capability records, vendor-specific webhooks, a Claude-specific todos field and a Codex-only goal-mode extension leak through the "common" API by design. Its flagship example, Polly, is a cross-vendor coordinator-worker: a Claude Code-brained orchestrator that writes no code, fans tasks to six vendor harnesses in per-task git worktrees, and mandates (in its prompt) that the reviewer be a different vendor from the implementer. Sandboxing is inconsistent on purpose: it wraps the Claude CLI in its own sandbox but delegates to Codex's native modes, evidence that OS isolation resists being factored out as a shared service. The twin absences hold here too, unless you count its two baseline dependencies, which are harness SDKs.

One tension. Hadfield et al. caution that coding has fewer truly parallel subtasks than research and that agents are not yet good at real-time delegation, yet seven systems ship coordinator-worker for coding. On inspection the patterns are used mostly for breadth-first exploration rather than parallel implementation, which reconciles the two once the unit of analysis is the workflow phase.

The minimalism argument (echoing CodeAct: code subsumes discrete tools): for benchmark evaluation alone, most production scaffolding is overhead. The counter-argument is that benchmarks don't see safety, streaming UX, extensibility, robustness (stuck detection, recovery) or cost management (caching, compaction, model selection).

Model–agent co-design runs both ways. The model shapes the agent: per-model prompts and tool modes (Codex), thinking budgets (Claude Code), routing to the cheapest sufficient model (Gemini CLI), per-model edit formats (Aider, OpenCode), model-specific tool presets (OpenHands). The agent shapes model usage: deferred loading changes the effective window, cache boundaries shape the prompt around economics, thought-stripping keeps caches clean, condensers decide what the model "remembers". Multi-provider systems need not design for the lowest common denominator; what they cannot replicate is the vendor's release-day update loop.

The scaffold–capability frontier, and what AHE's ablation adds

The paper's frontier picture (floor, steep early gains from a bash tool, a file tool and a context file, then a plateau where further work pays off in operational concerns) is explicitly a hypothesis. An operational test would fix a task distribution T, a model M, a complexity metric and a success target p, and find the lower envelope of scaffold complexity that exceeds p. The minimum surely varies with task complexity (multi-file refactors), safety requirements and interaction patterns (long sessions need memory).
